# Evidence Record

## Evidence summary

Mature production design systems extend beyond typography and buttons into components such as sliders, toggles, data tables, date pickers, file uploaders, trees, menus, popovers, progress indicators, coachmarks, and other advanced patterns.

## Exact claim supported or contradicted

A polished shared design system should include advanced reusable components when they solve repeated difficult interaction problems rather than limiting itself to simple styling primitives.

## Source provenance

Public documentation from established production design systems.

## Relevant excerpt or data

Carbon documents slider, toggle, data table, tree view, date picker, file uploader, menu, popover, and shell components. Spectrum Web Components documents advanced patterns including switch, menu/action-menu, and coachmark.

## Interpretation

The proposed catalog is consistent with the scope of mature systems, while the Echelon requirements remain stricter about native-first behavior and Ordo/application authority.

## Limitations

The existence of a component in another design system does not prove Echelon needs it or should copy its API or visual style.

## Counterevidence

Large catalogs create maintenance cost, which is why the Echelon catalog uses priority levels and explicit non-goals.

## Reproduction or verification notes

Re-evaluate P2/P3 components against actual consuming-application demand before implementation.
